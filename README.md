# ヘルスログ

**バージョン: v1.25**(`index.html`の設定タブ下部・`sw.js`・`worker.js`の版数表記と揃えています。更新のたびにこの4か所を一緒に上げてください)

食事・運動(筋トレ・有酸素・家事)・からだ(体重など)をできるだけ気軽に記録して、
摂取カロリーと消費カロリーの収支からダイエット・増量の指標にするための、
スマホのホーム画面に追加して使う個人用アプリです。

- 記録はすべてこの端末のブラウザ(localStorage)だけに保存されます。外部のサーバーには送られません。
- 唯一の例外が「🔍 AIで栄養を調べる」「📷 写真から記録」「📷 体重計の表示を撮る」「🔍 AIで運動強度を調べる」の4つのAI機能です。この4つだけ、あとで設定するAI中継サーバー(Cloudflare Workers)を経由してAI(Groq/Gemini)に食品名・写真・運動名を送り、概算や読み取り結果を受け取ります。
  - 「🔍 AIで運動強度を調べる」は既存のWorker(`worker.js`)がそのままでも動きます(未対応のpresetは自動的に栄養検索と同じ設定にフォールバックします)。今回同梱した`worker.js`に再デプロイすると、少しだけ応答が軽くなります(必須ではありません)。
- Google Sheetsなどのクラウド同期は行いません。バックアップは「設定」タブの「⬇️ JSONで書き出し」で行ってください。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体(これ1つで動きます) |
| `sw.js` | オフラインでも起動できるようにするためのファイル(`index.html`と同じ場所に置く) |
| `worker.js` | AI機能(栄養検索・写真判定)を中継するCloudflare Workers用スクリプト(開発者がデプロイする。利用者は触りません) |

## 配布までの手順(開発者向け)

利用者(このアプリを使う人)は、URLを開くかホーム画面のアイコンをタップするだけで使えるようにしてください。
以下はすべて、配布前に**開発者(あなた)が一度だけ**行う作業です。

### 1. AI中継サーバー(Cloudflare Workers)をデプロイする

AI機能(栄養検索・写真判定)を使うなら必要です。使わない場合はこの手順は飛ばして構いません(記録・グラフなどの基本機能はAI設定なしでも全部動きます)。

1. [Cloudflareのダッシュボード](https://dash.cloudflare.com)にアクセスし、アカウントを作成(無料)してログインします。
2. 左メニューの「Workers & Pages」を選びます(見えない場合は下の「Workers & Pagesが見当たらないとき」を参照してください)。
3. 「Create application」(または「作成」)ボタンを押すと、テンプレートを選ぶ画面になります。「Hello World」のような最小構成のテンプレート(または"Start with Hello World"のようなもの)を選び、名前を適当に付けて(例: `health-log-ai`)「Deploy」を押すと、ひな形のWorkerが作られます。
4. デプロイ後の画面で「Edit code」(または「コードを編集」)を開き、中身を全部選択して削除し、このリポジトリの `worker.js` の中身を丸ごと貼り付けて「Deploy」(保存・再デプロイ)します。
5. Workerの管理画面 →「Settings」→「Variables and Secrets」(バージョンによっては「変数とシークレット」)を開き、次の3つを**Secret(シークレット)**として追加します。
   - `APP_TOKEN` … このWorkerを呼び出すための合言葉。自分で好きな文字列を決めてください(英数字20〜40文字程度のランダムな文字列を推奨。パスワード生成ツールなどで作ると安全です)。
   - `GROQ_API_KEY` … [console.groq.com](https://console.groq.com) で無料アカウントを作り、APIキーを発行して貼り付けます(クレジットカード登録不要。推奨)。
   - `GEMINI_API_KEY` … [Google AI Studio](https://aistudio.google.com) で無料のAPIキーを発行して貼り付けます(任意ですが、Groqと両方設定しておくと安定します)。
   - どちらか一方のキーだけでも動きますが、両方設定しておくと片方が混雑・不調のときにもう片方へ自動で切り替わります。
6. 保存すると、Workerの管理画面に `https://health-log-ai.あなたのサブドメイン.workers.dev` のようなURLが表示されます。これが次の手順で使うWORKER_URLです。

#### 「Workers & Pages」が見当たらないとき

無料アカウント作成直後に、左メニューに「Workers & Pages」自体が出ていなかったり、出ていても「Create application」ボタンが反応しないという報告が一部の新規アカウントで見つかっています。ドメインの登録やプラン契約は不要で、無料アカウントでもWorkersはそのまま使えるはずの機能なので、以下を順番に試してください。

- 一度ログアウトしてから再ログインする、または別のブラウザ・シークレットウィンドウで開き直す
- ブラウザのキャッシュ・Cookieを削除してから開き直す
- `https://dash.cloudflare.com/?to=/:account/workers-and-pages` に直接アクセスしてみる(サイドメニューの検索や表示に頼らず、直接その画面へ飛べることがあります)
- それでも「Workers & Pages」自体が出ない・ボタンが押せない場合は、アカウント側の一時的な不具合の可能性があります。しばらく時間をおいて再度試すか、Cloudflareのサポート([support.cloudflare.com](https://support.cloudflare.com))に問い合わせてください。

### 2. `index.html` にWorkerの情報を埋め込む

`index.html` を開き、`// ============ CONFIG ============` という見出しのすぐ下にある、以下の2行を書き換えます。

```js
const WORKER_URL = "";
const WORKER_TOKEN = "";
```

```js
const WORKER_URL = "https://health-log-ai.あなたのサブドメイン.workers.dev";
const WORKER_TOKEN = "手順1のAPP_TOKENと同じ文字列";
```

これで、利用者側は何も設定せずにAI機能が使える状態になります。

AI機能を使わない場合は、この2行を空欄のままにしておいてください。その場合、記録・グラフなどの基本機能はそのまま使えますが、「🔍 AIで栄養を調べる」「📷 写真から記録」「📷 体重計の表示を撮る」「🔍 AIで運動強度を調べる」の4つだけ「⚠️ AI機能は現在ご利用いただけません」と表示されて動きません(カロリー・体重・体脂肪率はいずれも手で入力でき、運動強度は「らくらく/ふつう/きつい」から選べます)。

### 3. 配布する

`index.html` と `sw.js` を同じフォルダに置いて、GitHub Pagesなど好きな場所でホスティングしてください。利用者にはそのURLを伝え、スマホのブラウザで開いて「ホーム画面に追加」してもらうだけで、アプリのように使えます。

- 一度オンラインで開いておけば、以降は電波が無い場所(地下のジムなど)でも起動できます。
- `sw.js` は必ず `index.html` と同じフォルダに置いてください。

## 利用者向けの使い方

1. 初回起動時に、年齢・性別・身長・体重・目標体重・週間トレーニング目標を入力します(2ステップ)。
2. 「今日」「食事」「からだ」「運動」「ストレッチ」「カレンダー」「設定」の7タブで記録します。タブを切り替えると、前のタブでスクロールしていた位置に関わらず、必ず画面の一番上から表示されます(v1.12)。
   - **「今日」タブの「今日のカロリー」表示を廃止(v1.16)**: 「今日」タブと「食事」タブの両方に同じ「今日のカロリー」が出ていて重複していたため、v1.16で「今日」タブ側を削除しました。カロリーの数字は引き続き「食事」タブでいつでも確認できます(「今日」タブには体重目標・週間トレーニング・カロリー収支の3つが残ります)。
   - **各タブの履歴は直近7日間だけの表示です**(v1.13)。記録が増えても各タブが際限なく長くならないよう、「食事」「からだ」「運動」「ストレッチ」の履歴・記録一覧はすべて直近7日間に絞っています。それより前の記録は次の「📅 カレンダー」タブからいつでも確認できます。
   - **📅 カレンダー タブ(v1.13で新設)**: 運動・体重・食事・ストレッチの**全データ**を1つのカレンダーにまとめて表示します。日付ごとに🔴運動/🟡体重/🔵食事/🟣ストレッチ/⚪コメントの印が付き、日付をタップすると、その日のダッシュボードが下に表示されます。「もっと前の記録を見たい」ときは、まずこのタブを開いてください。
   - **📝 日ごとのコメント入力(v1.25で追加)**: カレンダーで日付を選ぶと、その日のダッシュボードの下に自由入力のコメント欄が表示されます。体調や出来事などのメモを、その日に運動・食事などの記録が無くても書き込めます。「💾 保存」で記録し、書いた日はカレンダーに⚪の印が付きます。「🗑️ 削除」でその日のコメントだけを消せます。
     - **日付のダッシュボード(v1.14で追加)**: 選んだ日の「摂取カロリー」「消費カロリー(運動・筋トレ/有酸素の内訳つき)」「体重(体脂肪率・腹囲があれば併記)」「ストレッチ(基本セットの達成数)」をKPIタイルでひと目にまとめ、食事を記録した日はたんぱく質・脂質・炭水化物の達成度メーターも表示します。その下に、これまで通り1件ずつの記録明細(編集・削除ボタン付き)も続けて表示されるので、ダッシュボードで様子を掴んでから、必要な記録だけ細かく直せます。数字はすべて他のタブ(今日・食事など)と同じ計算式を使っているので、食い違うことはありません。
       - **v1.15の修正**: 「摂取カロリー」の目標値に、その日の運動の消費が正しく反映されるようにしました。安全のため目安カロリーが下限で頭打ちになっている日は、運動の消費がまず「食事だけでは目標ペースに届かない不足分」の穴埋めに使われ、それを超えたぶんだけ目標に上乗せされる仕様のため、運動を記録しても目標値が動かない(=全額が穴埋めに使われた)ことがあります。この場合にその理由(「今日の運動○kcalは、食事だけでは足りない赤字の穴埋めに使っています」等)を添えて表示するようにし、運動分が反映されていないように見える問題を解消しました。
   - 「運動」タブでは筋トレ・有酸素運動に加えて、**家事**(掃除機がけ・拭き掃除・料理など、よくある家事があらかじめ登録済み)も消費カロリーとして記録できます。内蔵に無い有酸素運動・スポーツ・家事は、設定タブの「有酸素・スポーツ マスタ」「家事マスタ」から自分で追加できます。
   - 有酸素運動には「⏱ 時間で入力」に加えて**「🚶 歩数で入力」**(v1.9で追加)・**「📏 距離で入力」**(v1.11で追加)があります。歩数を入れると、設定タブに登録した身長から歩幅を概算し、距離・時間・消費カロリーに自動換算して「ウォーキング」として記録します(身長が未登録の場合は仮の値(165cm)で計算します)。距離を入れると、ペース(時速8.0km)から時間・消費カロリーを概算して「ランニング」として記録します。距離そのものは入力値をそのまま実測として記録します。
   - 運動タブの履歴には、**ランニング・ウォーキングの距離**(v1.10で追加)が添えて表示されます。歩数・距離で入力した記録は実測に近い距離をそのまま、⏱時間で入力した記録は内蔵のMET値が想定するペース(ランニング8.0km/h・ウォーキング4.8km/h)から概算した距離を「約○km」として表示します(実測ではなく目安である旨が伝わるよう「約」を付けています。ランニングは走る人によってペースの差が大きいため、あくまで参考値です)。
   - **🏃 移動距離の記録**(v1.11で追加): 運動タブの「進捗」カードの下に、ランニング・ウォーキングの距離だけをまとめた専用の一覧(直近7日間)が表示されます(通常の履歴とは別枠)。「進捗」カードには、週ごとのランニング・ウォーキングの合計距離を示す棒グラフ(直近8週・ランニングとウォーキングを積み上げ表示)も追加されました。
   - **📷 マシンの表示を撮る**(v1.18で追加): 運動タブの「⏱ 時間で入力」に、エアロバイクやランニングマシンなど、ジムのマシンのコンソール表示を撮るだけで「時間(分)」欄を自動入力できるボタンを追加しました。体重計の表示読み取りと同じ仕組みで、AI設定済みの場合のみ使えます。マシンに距離表示があれば、読み取った距離もあわせて案内します。マシン側のカロリー表示も読み取りますが、これは参考値として案内するだけで、実際に記録されるカロリーは他の運動種目・体重計と同じ、アプリ内のMET計算(体重×時間から算出)を使います(マシンによってカロリー表示の精度にばらつきがあり、種目ごとに計算方法が変わると収支グラフの数字が食い違って見えてしまうため)。読み取った値は入力欄に入るだけなので、数字が合っているか確認してから「＋ 記録する」を押してください。
   - **🗺️ 旅の記録(v1.22で追加)**: 「運動」タブの一番上に、ウォーキング・ランニング・バイクで記録した移動距離の合計を、好きなルートの道のりに見立てて進めていく、おまけの楽しみ機能を追加しました。「東海道の旅(500km)」「日本縦断(3,000km)」「ユーラシア横断(10,000km)」「世界一周(40,000km)」の4ルートから選べます(複数のルートをいつでも選び直せます)。選んだ時点からあとに記録した距離だけが進捗になるので、別のルートに切り替えても、それまでの距離を使い回して一気にゴールしてしまうことはありません。筋トレの量は(距離に換算する決まった基準がないため)含めていません。バイクは距離の実測入力が無いため、時速15km換算の概算距離を使っています。
   - **📋 部位ごとの実施状況をタップで展開(v1.21で追加)**: 「運動」タブの「📋 部位ごとの実施状況」(しばらくやっていない部位が上に来る一覧)で、部位の行をタップすると、その部位に登録している種目ごとに「直近いつ・何kg×何回やったか」が展開表示されます。種目名を入力せず部位だけで記録した履歴は「(種目名なし)」としてまとめ、登録はしたけどまだ一度もやっていない種目は「未実施」と表示されます。
   - **ホーム画面のアイコン(v1.19で追加、v1.20でデザイン変更)**: 今まではホーム画面に追加すると、ページのスクリーンショットのような味気ないアイコンになっていました。v1.19でオリジナルアイコンを追加し、v1.20でユーザー提供のイラスト(トレーニングウェア姿のキャラクター+「HEALTHLOG」ロゴ)に差し替えました。`index.html`の`<head>`内に画像を埋め込んであるだけなので、追加のファイルを配置する必要はありません。すでにホーム画面に追加済みの人がアイコンを更新したい場合は、一度ホーム画面のアイコンを削除してから、Safariでページを開き直して「ホーム画面に追加」をやり直してください(iOSの仕様上、追加済みのアイコンは自動更新されません)。
   - 「ストレッチ」タブ(v1.7で追加)は、デスクワークで座りっぱなしになりやすい部位・筋トレ後の回復ケアを踏まえた「毎日の基本セット」(7項目)にチェックを付けていく画面です。全部チェックした日が連続すると🔥で連続日数が表示されます。他に、道具や補助者なしで1人でできる「おすすめ」項目も部位別に用意しています。どの項目も「やり方」の説明付きです。カロリー計算には影響しない、体のケア専用の記録です。AI機能は使わないので、Workerの再デプロイは不要です。
     - **⏱ タイマー(v1.8)**: 各項目に「⏱ N秒で開始」ボタンがあり、押すとカウントダウンが始まります。0になると音とバイブでお知らせして、自動でチェックが付きます。同時に動くタイマーは1つだけで、他のタブに移動したり手動でチェックを変えたりすると止まります(記録と食い違わないようにするためで、途中で止めても完了扱いにはなりません)。
     - **🎯 今日のおすすめ3つ(v1.8)**: タブの一番上に、まだやっていない項目の中から「しばらくやっていない項目」を優先して3つ表示します。日付をもとに決めているので、同じ日にリロードしても毎回同じ3つが出ます(日が変われば別の3つになります)。全部チェック済みの日は達成メッセージに変わります。
     - **📅 直近7日間の記録(v1.8で追加、v1.13で月カレンダーから変更)**: タブの一番下に、直近7日間・日ごとの基本セット達成数とチェックした項目名を表示します。それより前の記録は「カレンダー」タブから確認できます。
   - 「食事」タブの「📷 写真から記録」は、撮った写真をAIに送って料理名・カロリーの候補を出す機能です(AI設定済みの場合のみ)。
   - 「からだ」タブの「📷 体重計の表示を撮る」は、体重計の表示部分を撮ると、体重と体脂肪率をAIが読み取って入力欄に入れてくれる機能です。スマート体重計でなくても使えて、機種の設定や連携も不要です。読み取った値は**入力欄に入るだけ**なので、数字が合っているか確認してから「＋ 記録する」を押してください(AIは読み間違えることがあります)。
   - 「からだ」タブの「📤 SNSにポストを作成」は、体重を記録すると経過をSNSへ投稿するための文章を自動で作る機能です。v1.15までは「Xの投稿画面を開く」「Blueskyの投稿画面を開く」の2つのボタンに分かれていましたが、「入り口が2つあって分かりにくい」とのご意見を受け、v1.16で「📤 投稿する」1つに統合しました。対応するスマートフォンではタップするとOS標準の共有画面が開き、その場でX・Bluesky・LINE・メールなど好きな送り先を選べます(共有画面が使えない環境ではXの投稿画面が開きます)。あわせて文章も**①からだ/②カロリー収支/③シンプル**の3種類から選べるようになりました(v1.16)。どれを選んでも自動投稿はされず、内容を確認してから最後はご自身で投稿します。
     - **基準日「今日/昨日」の選択(v1.17で追加)**: 「今日はまだ記録の途中」「昨日の分をあとから投稿したい」というときのために、ポストの基準日を「今日」「昨日」から選べるようにしました。「昨日」を選ぶと、今日つけた体重・食事などの記録を除いた、昨日時点までの内容(体重・体脂肪・その日のカロリー収支・累計収支)でポストが作られます。
3. 「設定」タブでできることは、目標設定(目標の種類「体重を変えたい/現状維持/筋力アップ」・体重目標・週間トレーニング目標・ペース)、マスタ登録(よく使う筋トレ種目・よく食べるもの・有酸素運動やスポーツ・家事の事前登録)、バックアップ(JSONの書き出し・読み込み)の3つだけです。むずかしい接続設定などは一切ありません。
   - 「筋力アップ」を選ぶと、体重を増減させるペース設定は使わず、基礎消費(TDEE)に少しの黒字を固定で足し、たんぱく質も多めにする計算に切り替わります。減量・増量のように体重目標のペースを気にする必要がありません。
   - 「現状維持」を選ぶと、目安カロリーは基礎消費(TDEE)と同じになります。
   - **📐 実測ベースのTDEE推定(v1.23で追加、v1.24で選択制に変更)**: プロフィール欄の下に、体重と食事の記録から実際の消費カロリー(TDEE)を逆算して表示するカードがあります。正確に記録していないとずれた値が出てしまう機能のため、既定は「オフ」で、カード上の「オフ/オン」チップで本人が選んで使う形にしています(選択は端末に保存され、次回起動時も覚えています)。「オン」にして体重と食事の記録(3週間以上・できるだけ毎日)がそろうと、「期間中の体重の増減(体脂肪1kg≒7200kcalで換算)」と「期間中の平均摂取カロリー」から、TDEE = 平均摂取カロリー − (体重の増減kg × 7200) ÷ 日数、という式で計算して表示します。年齢・身長などから計算式で見積もる上のBMR/TDEEとは別の、記録の実績にもとづく推定値です。できるだけ長い期間と、その半分程度の直近期間の2通りで計算してクロスチェックしており、両者が大きくずれている場合は記録にムラがある可能性がある旨を添えて表示します。体重か食事の記録に抜けが多い(期間の8割未満しか食事を記録していない)場合は、信頼できる推定ができないため表示されません。
   - 「有酸素・スポーツ マスタ」「家事マスタ」では、テニス・料理など内蔵に無い種目を名前で登録できます。運動強度は「らくらく/ふつう/きつい」から選ぶだけでOKですが、「🔍 AIで運動強度を調べる」を押すと、AIがその種目に近い数値を自動で入れてくれます(AI設定済みの場合のみ。未設定でも「らくらく/ふつう/きつい」で登録できます)。
4. 記録はこの端末にしか保存されないため、機種変更やブラウザのデータ消去に備えて、ときどき「設定」タブの「⬇️ JSONで書き出し」でバックアップを取ってください。「⬆️ JSONから復元」で戻せます。

## 計算方法について

- **基礎代謝(BMR)**: 体脂肪率が未記録のときは、**国立健康・栄養研究所の式**(20〜70歳代の日本人を対象に作られた推定式)で計算します。海外で広く使われるMifflin-St Jeor式は日本人の体格では低めに出やすいため、v1.6でこちらに変更しました。目安カロリーの内訳カードには、比較用にMifflin-St Jeor式の値も併記されます。年齢が20歳未満・80歳以上の場合は適用範囲外である旨の注意が表示されます。
- 体脂肪率を記録している場合は、除脂肪体重から求める**Katch-McArdle式**に自動で切り替わります(体組成が分かる場合はこちらが最も精度が高いため)。直近3件の平均を使うので、1回の測定のブレで目標が揺れません。
- **基礎消費(TDEE)** = 基礎代謝 × 日常生活の活動量(1.2〜1.5)。この係数は**運動を含まない生活活動のみ**で、運動による消費は記録した内容からMETs法で実測分だけを別途加算します。一般的なTDEE計算サイトの係数(1.2〜1.9)は運動込みの値なので、数字は一致しません。そのぶん、運動した日だけ目標カロリーが増える仕組みになっています。

## Workerの運用について(開発者向け補足)

- Cloudflare Workersの無料枠は1日10万リクエストまでで、個人利用であれば十分足ります。
- Groq・Geminiもそれぞれの無料枠の範囲で使う想定です。
### APP_TOKENは「秘密」ではありません(重要)

`APP_TOKEN` は配布する `index.html` の中に書かれます。利用者向けの設定画面には表示されませんが、**ブラウザのソース表示や開発者ツールを開けば誰でも読み取れます**。したがってこのトークンは「無関係な第三者からの素朴なアクセスを弾く鍵」であって、本気で調べる人に対する防御にはなりません。**URLを渡した相手は、事実上あなたのAPIキーを使う権利を持つ**と考えてください。

- 知り合い数人に渡す程度であれば、この設計のままで実用上問題ありません。
- URLを不特定多数に広める場合は、Cloudflareダッシュボードの Security →「Rate limiting rules」で、このWorkerのURLに対して1分あたり・1IPあたりのリクエスト数に上限を設けてください(無料プランでも1ルール設定できます)。
- 使いすぎや不審なアクセスに気づいたら、`APP_TOKEN` を新しい文字列に変更し、`index.html` の `WORKER_TOKEN` も同じ値に直して配り直してください。これで古いトークンは無効になります。
- 心配な場合は、AI機能を使わない設定(`WORKER_URL`/`WORKER_TOKEN`を空欄)で配布することもできます。記録・グラフなどの基本機能はすべて動きます。

### その他

- 画像は、アプリ側で縮小してから送信します(食事の写真は長辺768px、体重計の表示は液晶の数字がつぶれないよう長辺1280px)。Worker側でも8MBを超えるものを拒否します(トークンが漏れた場合に、巨大な画像で無料枠を一気に消費されるのを防ぐため)。
- 体重計の読み取りは既存のWorkerのままで動きます(画像判定はpreset設定を参照しないため)。再デプロイは不要です。
- AI側の障害はHTTP 502、無料枠・レート制限に当たった場合はHTTP 429を返します。Cloudflareのログや外形監視で異常として検知できます(利用者の画面に出る日本語の案内文は従来どおりです)。
